[[section-design-decisions]]
== Architekturentscheidungen

=== Warum gibt es viele Repositories und Erweiterungen statt einem zentralen UMTHES-Repository?

iQvoc startete als erweiterbares Produkt, das auf die Anforderungen verschiedener Kunden konfiguriert werden kann.
Weil nicht alle Erweiterungen für jeden Kunden relevant waren, sollten sie nicht Teil der Kernanwendung sein. Um bei
allen Kunden immer die Basisteile einsetzen zu können, sind sie als OSS veröffentlicht, die auch von anderen Entwicklern
und Unternehmen ohne INNOQ-Bezug eingesetzt werden. INNOQ arbeitet aktuell nur noch für SNS an iQvoc, so dass diese
Strategie inzwischen obsolet ist und der Code auch einfach in die jeweiligen Anwendungsrepositories gemerged werden
könnte. Das könnte aber zur Folge haben, dass für die einzelnen SNS-Anwendungen der Code doppelt geändert werden müsste.

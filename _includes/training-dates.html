{%- comment -%} Learn from the originals (2026-09-10): the arc42 team's training note, with the NEXT DATE OF EACH COURSE, rendered at build time from _data/trainings.json. That file is the expiry-filtered copy of https://trainings.arc42.org/api/trainings.json that .github/workflows/refresh-trainings.yml commits weekly and on demand; the same integration docs.arc42.org, faq.arc42.org, arc42.org and arc42.de run. Rendering rules: · one row per course, its earliest upcoming date, rows in date order. Not the next N dates across all courses, as docs renders: on a home page four rows that show four different courses say more than five rows of which three are the same one. The feed's course order is not used. · expiry-filtered again here (belt and braces over the workflow's filter), so a stale data file degrades to fewer rows, never to an ended course. · cancelled and full dates are skipped; a course whose only remaining dates are cancelled or full has no row. Waitlist renders with a marker. · every row carries a visible DE/EN badge. Language is a required feed field so no consumer has to guess it from a city name. · course links prefer the English detail page (url_en), falling back to url. · zero rows degrades to the sentence and the link. The sort walks every course once, collecting "start|course_index|date_index" for the first admissible date: Liquid cannot sort across nested arrays, but it can sort strings, and ISO dates sort lexicographically. The trainer claim is precise on purpose: most classes are taught by the two people who created arc42, but not all.
